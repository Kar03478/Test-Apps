GLBP Gateway Load Balancing Protocol

Conceptes clau

AVGActive Virtual Gateway — assigna MACs als clients
AVFActive Virtual Forwarder — encamina el tràfic real
VIPIP virtual compartida per tots els routers del grup
WeightingPes de cada AVF per al load balancing
PreemptPermet recuperar el rol d'AVG automàticament
⚡ El preempt de GLBP és per defecte desactivat (diferent de VRRP)

Lògica d'histèresi AVF

Pes inicial
weighting <base> lower <L> upper <U>
AVF es desactiva sipes < lower
AVF es reactiva sipes > upper
Track decrementpes -= decrement si ruta/i·f cau
⚠ Si lower == upper, qualsevol fallada que faci baixar el pes per sota activa/desactiva immediatament

Load balancing weighted

% tràfic router X
pes_X / (pes_R1 + pes_R2) × 100

Si un AVF es desactiva, el 100% va a l'altre. Si tots dos estan desactivats, no hi ha servei.

Round Robinalternança simple, sense pesos
Weightedproporció segons weighting

Configuració completa GLBP

Router 1 (AVG principal)

! Interfície cap als clients
interface FastEthernet0/0
 glbp 1 ip 192.168.1.3       ! VIP
 glbp 1 priority 110         ! AVG si és el més alt
 glbp 1 preempt              ! reclamar AVG si es recupera
 glbp 1 load-balancing weighted
 glbp 1 weighting 20 lower 7 upper 8
 glbp 1 weighting track 1 decrement 10
 glbp 1 weighting track 2 decrement 10

! Tracks (miren si la ruta existeix)
track 1 ip route 35.0.0.0 255.0.0.0 metric threshold
 threshold metric up 34 down 35
track 2 ip route 56.0.0.0 255.0.0.0 metric threshold
 threshold metric up 34 down 35

! Monitorar canvis d'estat

Tracks per interfície

track 1 interface FastEthernet0/1 line-protocol
! Es desactiva si la i/f cau físicament

track 2 ip route 10.0.0.0 255.0.0.0 reachability
! Es desactiva si la ruta desapareix

Taula de càlcul de pesos

SituacióPesEstat AVF
Tot OKbase (ex: 20)ACTIU
1 track cau (−10)20−10=10ACTIU si 10 > lower
2 tracks cauen20−20=0INACTIU
Track torna+10ACTIU si pes > upper
⚠ L'estat AVF persisteix entre temps — l'histèresi és acumulativa
VRRP Virtual Router Redundancy Protocol

Conceptes clau

Masterrouter amb prioritat més alta (defecte 100)
Backuprouter en espera
VIPIP virtual que reben els clients com a gateway
PreemptACTIVAT per defecte (diferent de HSRP)
Advertisement1 segon per defecte
Master Down~3 segons (3 × adv + skew)

Configuració bàsica

! Master (R1)
interface FastEthernet0/0
 vrrp 1 ip 192.168.1.3
 vrrp 1 priority 110
 vrrp 1 preempt         ! opcional, ja és default

! Backup (R2)
interface FastEthernet0/0
 vrrp 1 ip 192.168.1.3
 vrrp 1 priority 90

VRRP amb Tracking

! Definir track
track 1 interface FastEthernet0/1 line-protocol
track 2 interface FastEthernet1/0 line-protocol

! Aplicar a VRRP
interface FastEthernet0/0
 vrrp 1 ip 192.168.1.3
 vrrp 1 priority 110
 vrrp 1 preempt
 vrrp 1 track 1 decrement 21
 vrrp 1 track 2 decrement 21
⚠ Decrement > diferència de prioritats per garantir canvi a la 1a fallada. Ex: 110−21=89 < 90 ✅

Doble grup VRRP (load balancing manual)

! R1: Master grup 10, Backup grup 20
interface FastEthernet0/0
 vrrp 10 ip 10.0.0.10
 ! sense priority → usa 100 (default)
 vrrp 10 track 1 decrement 20
 vrrp 20 ip 10.0.0.20
 vrrp 20 priority 90   ! Backup grup 20
 vrrp 20 track 1 decrement 20

! R2: Master grup 20, Backup grup 10
interface FastEthernet0/0
 vrrp 10 ip 10.0.0.10
 vrrp 10 priority 90
 vrrp 20 ip 10.0.0.20
 ! sense priority → usa 100 (default)
c1 → gateway 10.0.0.10  |  c2 → gateway 10.0.0.20

Verificació VRRP

show vrrp brief
show vrrp interface FastEthernet0/0
! Veure Master addr, prioritat, estat

! Wireshark: filtre per veure failover
vrrp or icmp or arp
ip.dst == 224.0.0.18   ! multicast VRRP
MAC virtual0000.5e00.01XX (XX = grup)
SLB Server Load Balancing

Modes d'operació

ModeDescripcióCal als servidors
NATSLB tradueix IP i portgateway → SLB
ForwardingSLB reencamina sense NATgateway → SLB + VIP a loopback
⚠ Mode Forwarding: els servidors reben paquets amb IP destí = VIP. Cal que la tinguin configurada o l'acceptin.

Farm mode NAT (port 80)

ip slb serverfarm FARM1
 nat server                ! mode NAT
 predictor roundrobin
 real 10.0.0.1 80
  weight 2
  inservice
 exit
 real 10.0.0.2 80
  weight 4
  inservice
 exit
exit

Farm mode Forwarding (port 8080)

ip slb serverfarm FARM2
 ! sense "nat server"
 predictor roundrobin
 real 10.0.0.3     ! sense port en Forwarding
  weight 3
  inservice
 exit
 real 10.0.0.4
  weight 9
  inservice
 exit
exit
❌ No posar port en mode Forwarding → error "Must configure nat server"

Virtual Server (VIP)

ip slb vserver VSERVER1
 virtual 10.0.0.20 tcp 80
 serverfarm FARM1
 inservice
exit

ip slb vserver VSERVER2
 virtual 10.0.0.20 tcp 8080
 serverfarm FARM2
 inservice
exit
💡 La comanda "client" és opcional — sense ella accepta de tothom

Routing necessari

Els servidors han de saber retornar les respostes al client:

! Als servidors R1, R2, R3, R4
ip route 0.0.0.0 0.0.0.0 10.0.0.10
! gateway = IP del SLB

! Al PC Linux
sudo ip addr add 11.0.0.100/8 dev tap0
sudo ip link set tap0 up
sudo ip route add 10.0.0.0/8 via 11.0.0.10 dev tap0

NAT Network Address Translation

NAT PAT (Overload) — el més comú

! Definir zona inside i outside
interface FastEthernet0/0
 ip nat outside     ! cap a Internet

interface FastEthernet1/0
 ip nat inside      ! cap als clients

! ACL: qui pot fer NAT
access-list 1 permit 10.0.0.0 0.0.0.255

! Regla NAT: surt per f0/0 amb overload (PAT)
ip nat inside source list 1
  interface FastEthernet0/0 overload
💡 La wildcard mask és l'invers: /24 → 0.0.0.255 | /8 → 0.255.255.255

Explicació de la comanda NAT

PartSignificat
inside sourceTradueix IPs origen des de zona inside
list 1Aplica l'ACL 1 per filtrar qui es tradu·eix
interface f0/0Tradueix a la IP d'aquesta interfície
overloadPAT: múltiples clients, mateixa IP, ports diferents

Verificació NAT

show ip nat translations
show ip nat statistics
debug ip nat

Flux NAT complet

Client 10.0.0.1:1234 → Server 8.8.8.8:80
         ↓ Router (NAT)
11.0.0.1:5000 → Server 8.8.8.8:80
         ↓ Resposta
8.8.8.8:80 → 11.0.0.1:5000
         ↓ Router (deNAT)
8.8.8.8:80 → Client 10.0.0.1:1234
✅ Transparent pel client — ell sempre veu la seva IP privada

OSPF

router ospf 1
 network 192.168.1.0 0.0.0.255 area 0
 network 11.0.0.0 0.0.0.255 area 0

! Eliminar OSPF
no router ospf 1

Rutes estàtiques

! Ruta cap a una xarxa
ip route 12.0.0.0 255.255.255.0 11.0.0.3

! Ruta per defecte
ip route 0.0.0.0 0.0.0.0 11.0.0.1

! Floating static (backup, metric alta)
ip route 192.168.1.0 255.255.255.0 11.0.0.2 10

sudo ip route del 10.0.0.0/8
