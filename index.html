GLBP Gateway Load Balancing Protocol

Conceptes clau

AVGActive Virtual Gateway — assigna MACs als clients
AVFActive Virtual Forwarder — encamina el tràfic real
VIPIP virtual compartida per tots els routers
PreemptDESACTIVAT per defecte (diferent de VRRP)
⚠ El preempt de GLBP cal posar-lo explícitament

Lògica histèresi AVF

Configuració
weighting <base> lower <L> upper <U>
AVF desactiva sipes < lower
AVF reactiva sipes > upper
Track decrementpes -= decrement quan ruta/i·f cau
⚠ L'estat AVF és persistent — histèresi acumulativa entre temps

Fórmula load balancing weighted

% tràfic router X
pes_X / (pes_R1 + pes_R2) × 100
Round Robinalternança simple sense pesos
Weightedproporció segons weighting
Least Connva al servidor amb menys connexions

Configuració completa

interface FastEthernet0/0
 glbp 1 ip 192.168.1.3
 glbp 1 priority 110
 glbp 1 preempt
 glbp 1 load-balancing weighted
 glbp 1 weighting 20 lower 7 upper 8
 glbp 1 weighting track 1 decrement 10
 glbp 1 weighting track 2 decrement 10

track 1 ip route 35.0.0.0 255.0.0.0 metric threshold
 threshold metric up 34 down 35
track 2 interface FastEthernet0/1 line-protocol

Verificació

show glbp brief
show glbp detail
debug ip slb real

Preempt i AVG

Si R1 té preempt i cau R1-F0/0 → R2 passa a AVG. Quan F0/0 es recupera → R1 torna a ser AVG gràcies al preempt. El preempt de R2 no juga cap paper aquí.

VRRP Virtual Router Redundancy Protocol

Conceptes clau

PreemptACTIVAT per defecte (diferent de HSRP/GLBP)
Priority defecte100 — sense posar priority
Advertisement1 segon per defecte
Master Down~3 segons (3×adv + skew)
MAC virtual0000.5e00.01XX (XX=grup)
Multicast224.0.0.18

Configuració bàsica

! Master (R1) — priority > 100
interface FastEthernet0/0
 vrrp 1 ip 192.168.1.3
 vrrp 1 priority 110
 vrrp 1 preempt    ! opcional, ja és default

! Backup (R2)
interface FastEthernet0/0
 vrrp 1 ip 192.168.1.3
 vrrp 1 priority 90

VRRP + Tracking

track 1 interface FastEthernet0/1 line-protocol
track 2 interface FastEthernet1/0 line-protocol

interface FastEthernet0/0
 vrrp 1 ip 192.168.1.3
 vrrp 1 priority 110
 vrrp 1 preempt
 vrrp 1 track 1 decrement 21
 vrrp 1 track 2 decrement 21
⚠ Decrement > diferència de prioritats. Ex: 110−21=89 < 90 → canvi a la 1a fallada ✅

Doble grup VRRP (load balancing manual)

! R1: Master grup 10, Backup grup 20
interface FastEthernet0/0
 vrrp 10 ip 10.0.0.10
 ! sense priority → 100 default → Master
 vrrp 10 track 1 decrement 20
 vrrp 20 ip 10.0.0.20
 vrrp 20 priority 90

! R2: Master grup 20, Backup grup 10
interface FastEthernet0/0
 vrrp 10 ip 10.0.0.10
 vrrp 10 priority 90
 vrrp 20 ip 10.0.0.20
 ! sense priority → 100 default → Master
c1 → gateway 10.0.0.10  |  c2 → gateway 10.0.0.20

Verificació + Wireshark

show vrrp brief
show vrrp interface FastEthernet0/0

! Wireshark — veure failover
vrrp or icmp or arp

Seqüència failover: anuncis VRRP paren → 3s silenci → ARP gratuït de la nova MAC → anuncis del nou Master.

VRRP per SLBs (2 circuits)

! Circuit 1 — xarxa clients (outside)
interface FastEthernet0/1
 vrrp 1 ip 11.0.0.254
 vrrp 1 priority 110  ! SLB1
 vrrp 1 preempt
 vrrp 1 track 1 decrement 30

! Circuit 2 — xarxa servidors (inside)
interface FastEthernet0/0
 vrrp 2 ip 10.0.0.254
 vrrp 2 priority 110
 vrrp 2 preempt
 vrrp 2 track 2 decrement 30
💡 PC usa 11.0.0.254 com a gateway. Servidors usen 10.0.0.254. Ambdós apunten a la VIP VRRP, no a la IP directa del SLB.

NAT Network Address Translation

NAT PAT (Overload) — el més comú

interface FastEthernet0/0
 ip nat outside

interface FastEthernet1/0
 ip nat inside

access-list 1 permit 10.0.0.0 0.0.0.255
ip nat inside source list 1
  interface FastEthernet0/0 overload
💡 Wildcard = invers de màscara: /24→0.0.0.255 | /8→0.255.255.255

3 maneres de restringir a un sol client

1. ACL estàndard

access-list 1 permit 192.168.1.10
! wildcard 0.0.0.0 implícita = exactament aquesta IP
ip nat inside source list 1 interface Fa0/0 overload

2. NAT estàtic

ip nat inside source static 192.168.1.10 11.0.0.3
! IP fixa, no PAT, bidireccional

3. Route-map

route-map F10 permit 10
 match ip address 1
ip nat inside source route-map F10 interface Fa1/0 overload

inside source vs outside source

inside sourceoutside source
TradueixIP origen des de insideIP origen des de outside
Zones típiquesF0/0=inside, F0/1=outsideF0/0=outside, F0/1=inside
Ping R1→R3✅ funciona❌ no funciona
Cas d'úsclients interns → Internethosts externs amb IP privada
⚠ outside source: el paquet entra per outside amb src=X, es tradueix a Y quan va cap a inside. El ping des de R1 falla perquè R2 no sap encaminar el paquet cap a inside.

NAT pool (no solapat)

! SLB1
ip nat pool SLB1_POOL 11.0.0.100 11.0.0.110
 prefix-length 24
ip nat inside source list 1 pool SLB1_POOL overload

! SLB2 — rang diferent!
ip nat pool SLB2_POOL 11.0.0.120 11.0.0.130

ip nat inside source list 1 pool SLB2_POOL overload
❌ Si els pools solapessin, dos clients de SLBs diferents podrien tenir la mateixa IP traduïda → col·lisió

⚠ Config 3 F0/0 Reply és buit perquè "outside source" només tradueix quan el paquet entra per outside (F0/0→F0/1). La resposta ja porta dst=10.0.0.2 directament.

Regla per omplir la taula

inside sourcetradueix src quan surt de inside→outside
outside sourcetradueix src quan entra de outside→inside
staticbidireccional: X↔Y sempre
F0/0 insideel paquet NO ha passat pel NAT encara
F0/1 outsideel paquet JA ha passat pel NAT

tap0 / Linux Connexió PC real ↔ GNS3

Crear i configurar tap0

# Instal·lar uml-utilities (si cal)
sudo apt install uml-utilities
# o Fedora:
sudo dnf install uml-utilities

# Crear interfície TAP (com a root)
sudo tunctl -t tap0 -u kaar   # usuari = whoami

# Activar
sudo ip link set tap0 up

# Assignar IP
sudo ip addr add 11.0.0.2/8 dev tap0
💡 Per saber el teu username: whoami o echo $USER

Rutes Linux habituals

# Afegir ruta cap a VIP/xarxa GNS3
sudo ip route add 10.0.0.0/8 via 11.0.0.254 dev tap0

# Eliminar ruta
sudo ip route del 10.0.0.0/8

# Veure totes les rutes
ip route show

# Veure IP de tap0
ip addr show tap0
⚠ Usar sempre la VIP VRRP com a gateway (ex: 11.0.0.254), no la IP directa del router (11.0.0.1). Així funciona el failover.

Per què TAP i no TUN?

TAPcapa 2 (Ethernet) — GNS3 necessita frames Ethernet
TUNcapa 3 (IP) — no serveix per GNS3

GNS3 connecta el teu PC real al Switch virtual mitjançant tap0. Sense tap0 activa i amb IP, el PC no pot enviar ni rebre paquets cap als routers simulats.
